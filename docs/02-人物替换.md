# 2. 逐镜人物替换

核心：本地 ComfyUI 跑 MiniMax H3 的视频编辑模式（Ref2VA）。输入是原镜头（`<Video 1>`）加上这个镜头出场的 AI 娘人设图（`<Picture 1>`、`<Picture 2>`……），输出是动作、镜头、节奏不变，但人物和字幕都换掉的新镜头。

## 环境

- 模型：`minimax_h3_hybrid_fl2va_ref2va_b25-49-int8`，文本编码 `qwen3vl_32b_minimax_h3_nvfp4_awq`，视频 VAE fp16
- 采样：`res_multistep` / `simple`，20 步
- 分辨率 1024×576；56 帧约 2.5 分钟（RTX 5090）
- 工作流模板：[workflows/h3_ref2va_video_edit.json](../workflows/h3_ref2va_video_edit.json)。参考图按连接顺序对应 `<Picture 1>`、`<Picture 2>`……

## 提示词：必须用官方格式

这是整个项目最关键的一条经验。

一开始用简短的自然语言提示词，结果模型几乎原样照抄原片，人没换、字没换。换成 MiniMax 官方 [h3-prompt-writing skill](https://github.com/MiniMax-AI/MiniMax-H3) 的 Ref2VA 六段格式后，同一个镜头一次就换对了。原因推测：官方网页版和 API 前面有一个改写器，会把随手写的话扩写成这种结构化格式；本地 ComfyUI 没有这一步，所以必须自己写成官方格式。

六段依次是：

1. `subject_definitions`：定义 `<Video 1>` 和每个 `<Subject N>`：外观来自哪张参考图，位置、姿势、动作来自原片里的哪个人
2. `summary`：以 `[video editing + reference generation] The target video is an edited version of <Video 1>.` 开头，一句话说清换了谁
3. `retention_analysis`：每个元素保留多少（`fully_preserved` / `partially_preserved`……）
4. `detailed_description`：逐镜头 `[Shot N]` 描述画面，多镜头时用 `At MM:SS.mmm` 标时间
5. `overall_soundscape`：`N/A`
6. `non_diegetic_music`：`N/A`（音轨后期换回原曲）

完整示例（055，柠檬 → Gemini）：[prompts/055.txt](../prompts/055.txt)。所有 63 个最终通过的提示词都在 [prompts/](../prompts/)，[prompts/index.csv](../prompts/index.csv) 列出每个单元用的版本、种子和参考图顺序。

## 经验

**1. 修改时一次只加一句**

验收发现问题后，只针对这个问题在提示词里加一句，不要整段重写。改得越多，越容易把原来对的地方改坏。

**2. 外观相近时写“对比句”**

原作角色和 AI 娘的发色相近，或者人物很远、很小、快速推拉时，模型容易以为“已经换好了”而不动。解决办法是直接写出对比：原片里这个人是什么样（例如“青蓝色短发、黄色蝴蝶结”），换成后是什么样（“深蓝长卷发、鲸鳍耳、鲸尾、蓝色蝴蝶结”）。

**3. 多镜头单元：剪辑点会漂移**

一个单元里有剪辑点时，H3 生成的剪辑点会比原片早或晚几帧。做法：生成后用场景变化分数找到真实剪辑点，再以它为界分别抽帧对齐原片（`overnight_queue.py` 的 `cut_selection`）。另外，不要为了凑长度把无关镜头拼进参考视频，实测会串画面。

**4. 字幕替换**

- 原片的竖排日文姓名换成英文时，英文顺时针转 90° 竖排，和原作排版一致；中文姓名保持正立。
- 原来写 `(A-1 Pictures)` 的所属行，换成每个人自己所在的 AI 公司。
- 只换大字姓名，职位标签和版式都保留。

**5. 视频编辑换不掉时：改用首帧图生视频**

041_043 是一个剪影远景切特写的镜头。视频编辑试了 5 版，输出和原片几乎一模一样（SSIM 约 0.94），模型把剪影当成“已经是目标人物”。最后的办法：

- 用生图做出远景和特写两张关键帧
- 用 H3 的首帧图生视频模式（`MiniMaxH3ImageToVideo`，不输入原片）分别生成两段；工作流见 [workflows/h3_i2v_first_frame.json](../workflows/h3_i2v_first_frame.json)
- 后期接起来，再按原片时间溶解到原片的书页画面

代码：`pipelines/anime_op/revise_041_043_i2v.py`。

**6. 静态字卡和道具：直接生图**

片名字卡（011）和三个道具特写（081 菜单、082 跑鞋、083 告示）是静止画面，直接用生图做一张图，再按原镜头帧数静止输出，比视频生成干净得多。道具内容也做了二创：家庭餐厅菜单换成 AI 校园版菜单，文字改成中文。

**7. 人工逐镜验收**

每个单元生成后都进本地验收页（`review_school_op.py`），人工逐个看：通过、打回并写备注。打回的按备注改提示词，排进夜间队列重跑（`overnight_queue.py`），第二天再看。73 个单元一共生成并验收了 118 个 H3 版本。

**8. 让电脑能用**

H3 跑起来时显卡满载，电脑基本不能用，还出现过一次黑屏死机。所以加了显卡温度守护（`gpu_guard.py`）：温度超过阈值就停，任务之间先降温再提交，大批量任务放在晚上跑。

## 云端尝试

也试过 OpenRouter 上的 Seedance 2.5（视频编辑接口不可用，只能用参考生成）和云端 H3 2K（约 $0.13/秒）。云端画质更好，但同一个一闪而过的人物，云端两次都没换掉，本地反而成功了。最终全片都用本地生成。
